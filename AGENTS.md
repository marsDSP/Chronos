## Project overview

Chronos is a **Nonlinear Delay Engine** JUCE audio plugin (see `README.md`). It is still early, but no longer a bare template: `ChronosProcessor::processBlock` builds `ChronosEngine::Params` from raw APVTS reads and calls `engine.process()`; the engine's per-sample chain is **wet delay (`FeedbackDelay`) → drive-gain → tanh saturation (Off/ADAA1/ADAA2 per `adaaOrder`, with `SaturatorMakeup` output makeup) → saturator latency alignment → wet HPF/LPF (`OutputFilterStage`: Digital `SimdSVF` or Analog Sallen-Key) → equal-power dry/wet crossfade → bypass blend → output gain → TPDF dither → quantization** to a target bit depth, driven by parameters owned by `ChronosParameters` over an `AudioProcessorValueTreeState`, and `createEditor()` returns a `ChronosEditor` (single-window card layout, rev G2). The wet generation is a single `FeedbackDelay` recirculating loop that owns the delay line (two `Pow2RingBuffer`s read via `FracDelayTap`/`BlockTapReader`, or a clocked `BrigadeLine` BBD core with an NE570 compander in BBD mode) and the in-loop diffuser; `feedback == 0` simply scales the loop gain to zero (single tap, no recirculation) — there is no separate `SimdDelayLine` path. The loop runs damp one-pole LP → loop-cut one-pole HP → DC blocker → equal-power cross-feed → loop tanh (hard-clip/ADAA1/ADAA2 per `loopSatOrder`, with `1/drive` makeup and a `loopTrim` from `SaturatorMakeup`), and the loop tap passes through an **in-loop Schroeder-allpass diffuser** (C7c: repeat n = n diffusion passes, so repeats progressively turn into a wash). It targets **Standalone**, **VST3**, and (on macOS) **AU** formats. The header-only DSP lives under `source/dsp/` (the wet delay line lives inside `FeedbackDelay` as two `Pow2RingBuffer`s read through `FracDelayTap`/`BlockTapReader`; `SimdDelayLine` remains only for its `maxDelaySamplesFor` sizing helper — no longer JUCE's `dsp::DelayLine`). C++23.

Identity (set in `CMakeLists.txt`): company `MarsDSP`, BUNDLE_ID `com.marsdsp.Chronos`, manufacturer code `MDSP`, plugin code `CHRO`, version `0.1.0`. Remote: `https://github.com/marsDSP/Chronos.git`, branch `main`.

## Project structure

- `source/` — plugin sources, globbed into the `Chronos` target via `file(GLOB_RECURSE ...)` for `*.{cpp,h,hpp}`.
  - `ChronosProcessor.{h,cpp}` — JUCE `AudioProcessor`, thinned to host glue (S3): `processBlock` builds `ChronosEngine::Params` from raw APVTS reads and calls `engine.process()`; the per-sample chain lives in `ChronosEngine`. Stereo in/out via `BusesProperties`, mono/stereo layouts supported, no MIDI in/out, not a synth. `getTailLengthSeconds()` returns the feedback-aware repeat tail: `repeatTail = min(delaySeconds · n, 60 s) + (kAlignBudget + kMargin)/sr`, where `n = ceil(−3/log10(feedback))` (clamped to `kMaxTailRepeats` = 240 when `feedback ≥ 1`), `delaySeconds` uses the tempo-synced delay when `delaySync` is on, `kMargin` = 32768 samples covers wet-path ring-down, and `kAlignBudget = SaturatorAlign::kBudget` is the saturator-stage latency budget. `processBlock` does not early-return on bypass; it calls `engine.setBypass(parameters.getBypass())` and the engine blends the wet path against a `kBudget`-delayed dry copy via a 10 ms `bypassSmoother_`. Wet generation is block-rate: once per chunk `fbDelay_.process(inL, inR, wetBufL_, wetBufR_, chunk)` runs the whole chunk through `FeedbackDelay` (which owns the `Pow2RingBuffer` delay, the in-loop diffuser, and the BBD core) into the arena-allocated `wetBufL_`/`wetBufR_` spans (chunked at `wetBufCapacity_ = 2× samplesPerBlock`, S1). The per-sample loop then reads dry from the channel pointers and wet from the wet buffers, applies `drive` (per-sample smoothed linear gain) then tanh saturation (Off/ADAA1/ADAA2 per `adaaOrder`, two scalar `double` instances per channel; `adaaOrder` is read once before the loop since switching order mid-block would tear the ADAA state) with `Math::outputMakeup` gain, aligns dry/wet through `SaturatorAlign` (`alignL_`/`alignR_`, `setMode`-ed once per chunk), shapes the wet through `OutputFilterStage` (Digital `SimdSVF` or Analog Sallen-Key; dry passes unfiltered), blends dry and wet via an equal-power crossfade (computed with the project's minimax `mmCos`/`mmSin`, not libm) (`dry*cos θ + wet*sin θ`, θ = mix·π/2), applies the bypass blend, then output gain (dB → linear via `Decibels::decibelsToGain`) → TPDF dither + quantization to the target bit depth, using per-channel 4-lane SIMD xorshift32 states with a scalar xorshift32 tail (seeded from `std::random_device`). The wet `OutputFilterStage` and the equal-power crossfade run 4-wide SIMD (`mmCos`/`mmSin` over a per-sample θ ramp) with a scalar tail for `chunk % 4`; the TPDF dither + quantization tail also has a 4-wide SIMD path (per-channel 4-lane xorshift32 states `xorshiftSimdL_`/`xorshiftSimdR_`) with a scalar xorshift32 tail, and is bypassed entirely when `bits ≥ 32` (no dither, no quantizer). The ADAA saturators and `SaturatorAlign` remain scalar `double` per channel (stateful IIR / sequential). The crossfade is comb-filter-free at its extremes (0% = dry only, 100% = wet only); the `mix` parameter defaults to 35% (a mid blend), so the default path mixes dry and wet. Dry and wet are aligned to a constant latency budget `kBudget = kHalfSampleTaps/2` (8 samples) via `MarsDSP::Align::SaturatorAlign` (`alignL_`/`alignR_`, one per channel): the dry path is delayed by `kBudget` (integer, so `mix = 0%` is bit-transparent apart from the latency — invariant I1), and the wet path is padded to `kBudget` per mode by the aligner placed directly after the saturator (saturator → alignment → SVF): Off pads the wet with an integer `kBudget` delay, ADAA2 with `kBudget − 1` (the ADAA2 triangle kernel supplies 1), and ADAA1 with the `HalfSampleFir` (the box kernel supplies 0.5, the FIR supplies `kBudget − 0.5`). All three wet totals equal `kBudget`, so reported latency is constant across `adaaOrder` (invariant I2, `setLatencySamples(kBudget)` called once in `prepareToPlay`); ADAA1 is now exactly aligned (the 0.5-sample residual the former 1-sample `dryZ1`/`wetZ1` mechanism left is gone — the FIR supplies the missing half sample). `adaaOrder` is read once before the loop and `alignL_`/`alignR_` are `setMode`-ed there (switching mid-block would tear the ADAA state and discontinuously change the alignment configuration); in the mono path `alignR_` is `reset()`/`setMode()`-ed but never called, so it is never fed stale data. `prepareToPlay` calls `parameters.prepare(sampleRate)` + `parameters.reset()`, then `engine.prepare(sampleRate, samplesPerBlock, numChannels)` (which sizes `wetBufCapacity_ = 2× samplesPerBlock` (S1), allocates all scratch buffers + the `FeedbackDelay` ring from one `BumpArena`, and calls `engine.reset()`), builds the initial `Params` and calls `engine.resetParams(p)`, and calls `setLatencySamples(MarsDSP::Align::SaturatorAlign::kBudget)`. `getBypassParameter()` is overridden to return the bypass param so hosts wire it natively. Parameters live in an `AudioProcessorValueTreeState` whose layout is built by `ChronosParameters::createParameterLayout()` and accessed via a `ChronosParameters` member (28 params; display names in quotes): `delayTime` (float, 1.0…5000 ms, skew 0.231, default 375), `delayTimeR` (float, 1.0…5000 ms, skew 0.231, default 375), `timeLink` (bool, default true), `delaySync` (bool, default off), `delayDivision` (choice: 1/64…4/1, 20 entries, default 1/4), `delayMode` (\"Delay Core\", choice: Digital / BBD, default Digital), `feedback` (float, 0…1.15, custom repeat-count mapping, default 0.42), `dampHz` (\"Repeat Damp\", float, 200…20000 Hz, default 8000), `loopCutHz` (\"Repeat Cut\", float, 20…2000 Hz, default 40), `crossFeed` (float, 0…1, default 0), `loopDrive` (\"Repeat Drive\", float, −6…+24 dB, default 0), `loopSatOrder` (\"Repeat Sat\", choice: Off / 1st / 2nd, default 2nd), `delayModDepth` (float, 0…50 cents, default 0), `delayModRateHz` (\"Delay Mod Rate\", float, 0.01…10 Hz, default 0.35), `enableDiffuser` (\"Diffuser\", bool, default off), `diffusion` (float, 0…1, default 0.55), `diffuserSize` (float, 0…1, default 0.5), `diffModDepth` (\"Diffuser Mod\", float, 0…1.5 ms, default 0.30), `diffModRateHz` (\"Diffuser Rate\", float, 0.01…8 Hz, default 0.35), `drive` (float, 0…24 dB, default 0; smoothed as linear gain via `Decibels::decibelsToGain`), `adaaOrder` (\"Drive Sat\", choice: Off / 1st / 2nd, default 2nd), `filterMode` (\"Output Filter\", choice: Digital / Analog, default Digital), `hpfFreq` (\"Output HPF\", float, 20…2000 Hz, default 20), `lpfFreq` (\"Output LPF\", float, 200…20000 Hz, default 20000), `mix` (float, 0…100, default 35), `gain` (\"Output Gain\", float, −24…+12 dB, default 0), `bits` (\"Bit Depth\", int, 4…32, default 32), and `bypass` (bool). Sections 2 and 5 carry quadrature-LFO delay modulation; section coefficients alternate sign per section (`sectionSign`, the signalsmith/Dattorro polarity-flip trick — changes phases, not energies, so stability, |H| = 1, and the transport below are unaffected). Chunked block processing (`kChunk` 16, 4-wide SIMD fast path when the size ramp is settled, per-sample fractional exact path otherwise; `processBlockRef` is the scalar reference twin). `baseTransportSamples(size)` is the series delay ΣDᵢ — and, by the allpass average-group-delay identity, the **exact energy centroid of the cascade IR at every g**; `transportSamples()` returns it (C7c: the tap/loop compensation anchors the exact centroid, replacing the old `w = 1−g⁸` energy-median estimate that let arrivals drift by up to `g⁸·base`).
  - `dsp/FeedbackDelay.h` (`MarsDSP::Delays::FeedbackDelay`) — the feedback-loop delay used when `feedback > 0`: chunked block processing over the loop-carried distance (sub-chunks `Lc ≤ D − kChunkGuard`, SIMD bulk tap read, scalar damp/DC/cross/ADAA recursion, bulk write). **C7c: the diffuser lives INSIDE the loop** — the loop-tap stream passes through a `Diffuser` member before the recursion (and the output), so repeat n = n diffusion passes (progressive wash). The loop tap reads at `d − satLatency_ − fade·baseTransport`: since `baseTransport` is the cascade's exact energy centroid at every g, the loop period stays exactly `d` per pass at all diffusion settings (repeat centroids land on `n·delay`, aggregate-verified to ±0.3 ms by `diffuser_loop_check`). The enable toggle is one fade variable driving both the raw/diffused tap blend and the comp (blend centroid = `fade·base` exactly, so comp stays exact mid-fade); `prime()` on the rising edge; Off (fade settled 0) is bypassed and bit-exact with the pre-C7c path. The old C7 output-tap machinery (`outputTapOffset_`, second bulk read) is deleted — the output is the (diffused) loop-tap stream itself. When `delay < baseTransport` the loop tap clamps at `kMinLoopDelay` and repeats land late by the remainder (same documented clamp semantics as C7). With `feedback == 0` the loop gain is zero — `FeedbackDelay` still runs and emits the single (optionally diffused) tap, so there is no separate `SimdDelayLine` path; a single repeat is identical across the feedback boundary because the same diffuser and `baseTransport` comp apply. `FeedbackDelay` also implements BBD mode (`delayMode == 1`): the tap comes from a clocked `BrigadeLine` (clock set per sample via `ClockModel::clockFor`) wrapped in the NE570 compander (`CompressorCell` write, `ExpanderCell` read), with the digital ring kept warm in parallel for mode-flip priming.
  - `dsp/align/` — header-only latency-alignment DSP for the saturator stage (not yet wired into the plugin). `HalfSampleFir.h` (`MarsDSP::Align`): symmetric half-sample-delay FIR that will compensate ADAA1's 0.5-sample box-kernel wet-path latency. Coefficients are a 16-tap Kaiser-windowed sinc at offset `D = (N−1)/2` (β ≈ 3.6, chosen by `scripts/python/halfsample_fir.py` to minimise max passband deviation over `[0, 0.42·fs]`; +0.046 dB at 15 kHz, structural Nyquist null at π), re-derived and regression-checked by that script. Symmetric by construction (`N` even ⇒ `D` half-integer ⇒ `sinc(m−D)` never hits the `sinc(0)` degenerate case, and the Kaiser window is symmetric), so the FIR is exact linear phase with group delay `(N−1)/2 = 7.5` samples — a half sample of intended fractional delay plus 7 samples of integer bulk delay. The tap line is a power-of-two circular buffer with a write index and mask (no per-sample `memmove` — C5); the coefficient pairs are folded (`h[j]·(z[j] + z[N−1−j])`) in the same accumulation order (j=0 newest+oldest first through j=N/2−1 middle last) so the multiply count halves and the accumulation is structurally symmetric and cannot drift from linear phase through FMA reassociation. `kHalfSampleTaps` (even, `static_assert` ≥ 4) and `kHalfSampleCoeffs` are `inline constexpr`; `kBulkDelay = kTaps/2 − 0.5` is the FIR's own group delay. Only ADAA1 will run the FIR; Off and ADAA2 modes use integer delays (exact). `ShortDelay.h` (`MarsDSP::Align`): a fixed-capacity integer delay template `ShortDelay<MaxDelay>` for the 0…`MaxDelay` sample range — deliberately not `SimdDelayLine` (block-rate, one-pole smoother, 6-tap interpolator, dual-read crossfade — none apply to a fixed integer delay, and coupling the alignment layer to the main delay engine is unwanted). `setDelay(0)` is a bit-exact passthrough (returns `x` directly, no ring round-trip — the off-by-one the spec flags as the most likely bug in the whole layer; a read-then-write ring with `d == 0` would silently hand back a full-ring delay instead of zero); `d ≥ 1` is read-then-write into a power-of-two `bit_ceil(MaxDelay+1)` ring (mask `&`, not modulo — C4), tap at `(w − d + cap) & mask`. Used by `SaturatorAlign` for the wet-path integer padding in Off and ADAA2 modes (and to leave ADAA1's wet at 0 integer delay so the FIR supplies the rest). `SaturatorAlign.h` (`MarsDSP::Align`): one instance per channel (matching the ADAA classes), tying the dry/wet latency alignment together. `kBudget = kHalfSampleTaps/2` (the constant reported latency; `static_assert kBudget >= 2` so ADAA2's `kBudget−1` integer delay stays ≥ 1). `processDry` always applies the integer delay `kBudget`; `processWet` is mode-dependent — `setMode(0)` (Off) → `wetInt_` at `kBudget` (FIR unused), `setMode(1)` (ADAA1) → `wetInt_` at 0 + the `HalfSampleFir` (the only mode that runs the filter), `setMode(2)` (ADAA2) → `wetInt_` at `kBudget−1` (FIR unused). Wet totals: Off `kBudget`, ADAA1 `0.5 + (kBudget−0.5) = kBudget`, ADAA2 `1 + (kBudget−1) = kBudget` — all equal `kBudget` and to dry, so reported latency is constant (I2) and dry/wet are aligned (I1). The FIR runs in mode 1 only, not in all modes, so its HF droop is not imposed on the two exact integer modes. Wet-chain order for the plugin: saturator → alignment → SVF (the layer is LTI so its position relative to the SVF is acoustically irrelevant, but directly after the saturator gives the "saturator stage" one well-defined total latency). Switching `adaaOrder` mid-stream discontinuously changes both the alignment configuration and the saturator kernel, so a small click is expected; a dual-chain crossfade to smooth it is a separate feature (documented in the header, out of scope here). Verified by `align_check` (Commit 4); wired into `ChronosProcessor` in Commit 5 (replacing the former 1-sample `dryZ1`/`wetZ1` mechanism). JUCE-free; links against `SharedCode`. NaN/inf hygiene: `SaturatorAlign::process{Dry,Wet}` scrub non-finite inputs to +0.0f, and `SimdSVF::processBlockStep` clears non-finite input lanes and resets latched non-finite state (never taken for finite signals — bit-exact), so a bad host sample can no longer latch the chain's IIR state.
  - `dsp/nonlinear/` — header-only nonlinear / antiderivative-antialiasing (ADAA) DSP. `Nonlinearities.h` (`MarsDSP::Nonlinear`): ADAA nonlinearity policies supplying `f`/`F1`/`F2` (all `double`) — `TanhNL` (`f = tanh`; `F1` and `F2` now delegate to `Math::f1Tanh`/`Math::f2Tanh` from `TanhAntiderivatives.h` — three-region minimax, no dilogarithm in the hot path; `signx` and `kPiSqOver24` deleted, `kLn2` kept for external callers) and `AlgebraicNL` (`f = x/√(1+x²)`, all-elementary `F1 = √(1+x²)`, `F2 = ½(x√(1+x²) + asinh x)` — the `Li₂` escape hatch and a second curve for the alias harness). `F1′ = f`, `F2′ = F1`; `F1` even, `F2` odd; `signx(0)=0` makes `F2(0)=0` exact. `ADAA1.h` (`MarsDSP::Nonlinear::ADAA1<NL>`): first-order ADAA baseline — divided difference of `F1` over the last two samples, midpoint `f(0.5·(x0+x1))` fallback when `|x0-x1| < 1e-4`, evaluates `F1(x0)` **unconditionally** (one `F1` eval per sample) and caches it on every path — skipping the eval on the fallback path would leave `F1x1_` holding `F1` of an older input than `x1_`, and a signal whose per-sample steps stay under the epsilon lets `x1_` drift arbitrarily far from the cached value; `alias_check` measured the resulting broadband error at −34 dBc on a 55 Hz sine (−121.8 dBc after the fix); half-sample (fractional) latency, so it is the `alias_check` A/B comparison path, not a release-quality one (the 0.5-sample residual against a 1-sample dry delay cannot be made integer). `ADAA2.h` (`MarsDSP::Nonlinear::ADAA2<NL>`): second-order ADAA — twice the second divided difference of `F2` over the last three samples `x0,x1,x2`, output aligned to `x1` for exactly 1 sample of **integer** latency (`kLatencySamples = 1.0`). Four branches in load-bearing order (`A=|x0-x1|`, `B=|x1-x2|`, `C=|x0-x2|`): (a) all three nodes coincident (`A<εᵢ` and `B<εᵢ`) → centroid `f((x0+x1+x2)/3)` (`O(Δ²)` residual vs a midpoint's `O(Δ)`; must precede (b), since small `A`,`B` imply small `C`); (b) confluent outer nodes (`C<ε₀`, the Nyquist-rate `…a,b,a,b…` alternation heavy saturation produces) → Hermite form `2·(F1(m02) - d1)/(m02 - x1)` with `m02 = ½(x0+x2)`; (c) inner quotient degenerate (`A<εᵢ` only) → `d1 = F1(½(x0+x1))`, folded into the `d1` assignment so it needs no separate arm; (d) generic formula. Caching identity: this sample's `d2` is last sample's `d1` (both `F2[x1,x2]`), cached after its own fallback, so one `F2` eval + one inner + one outer quotient run per sample and the symmetric `B<εᵢ` case is free. `εᵢ = 1e-4`, `ε₀ = 1e-6` (`kEpsInner`/`kEpsOuter`), both tuned in `adaa2_check` and justified in the header comment: each epsilon sits where its fallback's truncation balances the cancellation of the exact formula it replaces. `ε₀` is **not** the spec's initial `1e-4` — branch (b) evaluates `F1` at `m02` but reuses `d1 = F2[x0,x1]`, which is first-order inconsistent once `x0 ≠ x2`, so it truncates at `O(C)` (`|y|·C/(2|m02-x1|)`), not `O(C²)`; at `1e-4` that measured 8.4e-6 (~−101 dB) where the generic formula would have given ~1e-7. Making the branch consistent (recomputing `d1` as `F2[m02,x1]`, one extra `F2` eval on that path only) would restore `O(C²)` and allow a larger `ε₀`. `double` internally — the nested divisions carry a `1/Δ²` cancellation term, so float32 would fire the coincident-node fallback for most samples at ordinary drive. `reset()` zeros all four state members (`x1_`,`x2_`,`F2x1_`,`d2_`). Verified by `adaa2_check`; no plugin wiring yet — a header the plugin does not include. JUCE-free; links against `SharedCode` like the rest of `source/dsp/`.

## Build

Chronos builds with CMake + JUCE. C++23, CMake ≥ 3.23.1. The primary workflow is CLion (`cmake-build-debug/`); standard CMake also works.

### Quick start

```sh
git clone --recurse-submodules https://github.com/marsDSP/Chronos.git
cd Chronos
cmake -S . -B build
cmake --build build
```

If you cloned without submodules:

```sh
git submodule update --init --recursive
```

### Prerequisites

- A C++23 toolchain (Xcode Command Line Tools on macOS).
- CMake ≥ 3.23.1 (Ninja optional; CLion ships its own generator).
- Python 3 (required by `CMakeLists.txt`).

### Targets

- `Chronos_Standalone`, `Chronos_VST3`, `Chronos_AU` (macOS only), `Chronos_All` — the plugin formats.
- `AudioPluginHost` — built from `libs/JUCE/extras/AudioPluginHost` (opt-in via `-DBUILD_AUDIO_PLUGIN_HOST=ON`; OFF is the default).
- `Run_AudioPluginHost_VST3` / `Run_AudioPluginHost_AU` (macOS) — build the plugin + host, then open `Audio Plugin Host.app` for scanning.
- `Print_Plugin_Paths` — prints the VST3/AU artifact locations.

Built plugins are written to `<build>/Chronos_artefacts/<Config>/` as **Standalone**, **VST3**, and (on macOS) **AU** (e.g. `cmake-build-debug/Chronos_artefacts/Debug/VST3/Chronos.vst3`).

### macOS / build gotchas (read before touching CMake)

- **Universal binary**: `CMAKE_OSX_ARCHITECTURES` is forced to `x86_64;arm64`; deployment target `11.0` (including the arm64 slice).
- **x86_64 FMA**: the plugin and harness targets compile with FMA enabled on all platforms so `simde_mm_fmadd_ps` lowers to `vfmadd*ps` on x86_64 (arm64 has FMA unconditionally and needs no flag). Apple uses `-Xarch_x86_64 -mfma` (the `-Xarch_` prefix scopes the flag to the x86_64 slice of the universal build; a bare `-mfma` would also reach the arm64 pass); Linux x86_64 uses bare `-mfma`; MSVC x64 uses `/arch:AVX2`. This raises the x86_64 baseline to Haswell/FMA3 (AVX2 on MSVC) — pre-Haswell CPUs (e.g. the 2013 Mac Pro, Ivy Bridge-EP, which has AVX but no FMA3) would take a SIGILL, so drop the flag if such hardware must keep working. Without it the code still builds — SIMDe falls back to a mul+add pair.
- **Warnings**: `-w` disables all warnings on non-MSVC compilers; JUCE recommended warning/LTO flags are still applied to the plugin target.
- **Debug symbols**: `-gdwarf-4` is added in `Debug`.
- **ObjC ARC**: on Apple, JUCE `.mm` sources and the plugin target are compiled with `-fno-objc-arc`.
- **Policy overrides**: `CMP0177` (install `DESTINATION` normalization) and `CMP0167` (Boost) are set to `NEW`. `CMAKE_POLICY_VERSION_MINIMUM` is not set, since no vendored lib currently needs it.
- **Submodule ordering**: `add_subdirectory(libs/JUCE)` runs at the top of `CMakeLists.txt`, before the macOS arch/deployment-target cache variables are set. This configures fine today, but if you add a vendored lib that reads `CMAKE_OSX_ARCHITECTURES` / `CMAKE_OSX_DEPLOYMENT_TARGET` at configure time, move those cache variables above its `add_subdirectory()`.
- **Post-build copy**: a `POST_BUILD` command on `Chronos_VST3` runs `scripts/bash/copy_vst3.sh`, gated by `-DCOPY_VST3_AFTER_BUILD=ON` (default OFF). The script takes the VST3 bundle path (`$1`, from CMake's `$<TARGET_BUNDLE_DIR:...>`) and the destination (`$2`, from the `VST3_COPY_DEST` cache variable, default `~/Desktop/vst test`).
- **JUCE submodule**: `libs/JUCE` is a marsDSP fork. If it is empty after clone, run `git submodule update --init --recursive`.

## Testing

Opt-in harnesses, gated by `-DBUILD_TEST_HARNESSES=ON` (OFF by default, so the default build is unchanged). `tests/CMakeLists.txt` defines thirty-three executables (27 registered with CTest: 21 correctness + 6 benchmarks labeled `bench`). Thirty-two link only the `SharedCode` INTERFACE target (no JUCE), so they pull in the `source/` + `libs/simde` include paths and `cxx_std_23` without the plugin modules; `delay_line_bench` additionally links `juce::juce_dsp` to get `juce::dsp::DelayLine` for the old-baseline comparison:

- `tan_bench` — `mmTan` (FMA `M128`) accuracy regression + throughput vs `std::tan`; forced `-O2` and `-Xarch_x86_64 -mfma` so the kernel inlines and `simde_mm_fmadd_ps` lowers to a fused multiply-add.
- `ring_buffer_check` — `Pow2RingBuffer` correctness vs a naive modulo oracle (zero state, block write + mirror invariant, exhaustive window read, interleaved sequence, large capacity). No forced `-O2` so the header's `assert` preconditions stay armed in a Debug configure.
- `halfsample_fir_check` — `HalfSampleFir` correctness: coefficient symmetry (bit-exact), DC gain, impulse-response centroid (`(N−1)/2`), flat group delay (< 1e-9 ripple over `[0, 0.9π]`), passband magnitude (gate > −0.1 dB at 15 kHz), Nyquist null, a dormant Lagrange cross-check at `kHalfSampleTaps == 6`, and reset reproducibility. Same conventions as `ring_buffer_check` (no forced `-O2`, `assert`/`static_assert` preconditions armed in Debug).
- `short_delay_check` — `ShortDelay<MaxDelay>` correctness: for every `d` in `[0, MaxDelay]`, impulse (exactly `1.0f` at sample `d`, `0.0f` elsewhere in `[0, 4·MaxDelay]`), ramp (`y[n] == x[n−d]` bit-exact over 1000 samples, many ring wraps), and reset reproducibility. Tested at `MaxDelay = 8` (the real `kBudget`) and `MaxDelay = 1` (the `d ∈ {0,1}` edge). Same conventions as `ring_buffer_check` (no forced `-O2`, `assert` preconditions armed in Debug).
- `align_check` — `SaturatorAlign` correctness: the property the whole layer exists for. (1) dry is an exact integer delay (impulse → `1.0f` at `kBudget`, zeros elsewhere, all three modes, bit-exact — I1); (2) wet total group delay equals `kBudget` in every mode (the ADAA stage kernel is prepended analytically — box `[0.5,0.5]` for ADAA1, triangle `[0.25,0.5,0.25]` for ADAA2 — before the alignment wet impulse response; centroid `== kBudget` to 1e-6, the headline test); (3) modes 0/2 are bit-exact pure delays (impulse → single `1.0f` at `kBudget`/`kBudget−1`); (4) mode 1 is linear phase (group-delay ripple < 1e-6 over `[0, 0.45·fs]` — I3); (5) dry/wet null (mode 0, same white-noise to both paths, bit-identical); (6) cross-mode phase coherence at 1/5/10/15 kHz (50/50 sum within 0.5% of the in-phase prediction — the test that would have caught a first-order-allpass design); (7) reset across all modes; (8) mode switching mid-stream (no NaN, bounded). Same conventions as `ring_buffer_check` (no forced `-O2`, `assert` preconditions armed in Debug).
- `latency_null_check` — end-to-end latency/alignment harness (`harnesses/dsp/latency_null_check.cpp`). Links `SharedCode` only and hand-assembles the DSP headers into the same chain order as `processBlock` (delay → saturator → alignment → [SVF] → equal-power crossfade), NOT the JUCE `AudioProcessor`. (1) full-dry null (`mix = 0%`: output == input delayed by `kBudget`, bit-exact, all three modes identical = I2); (2) full-wet Off saturator-bypassed (output == input delayed by `delaySamples + kBudget`, to 1e-5); (3) 50% mix Off sine sweep 20 Hz–20 kHz, gate ±0.05 dB (the acceptance test — any residual misalignment appears as a comb); (4) 50% mix ADAA1/ADAA2 small-signal sweep to 15 kHz, gate ±0.2/±0.1 dB. Tests 3–4 compare the 50% sum against the predicted in-phase sum of dry-only and wet-only (measured separately), which cancels the ADAA kernel's own low-pass droop (box `|cos(πf/fs)|` for ADAA1, triangle `cos²(πf/fs)` for ADAA2 — −2.2/−3.7 dB at 15 kHz in the raw 50/50 sum) and isolates alignment, which is the spec's intent ("a failure here that passes test 3 means the mode-dependent branch in `setMode` is wrong"); the spec's literal "near-flat" wording is unachievable for ADAA1/ADAA2 because the kernels droop. The wet SVF and dither/quant tail are wired into the chain but gated off (LTI / signal-orthogonal, sit after the aligner on the wet path only, cannot affect alignment; enabling them would confound the tolerances). Same conventions as `ring_buffer_check` (no forced `-O2`).
- `simd_delay_check` — `SimdDelayLine` correctness: integer impulse (3 modes), polynomial reproduction / centroid (3 modes, the flaw-B sign-error guard), stereo independence, multi-block delay, delay-move settling (20 ms one-pole convergence), ring-wrap endurance (~250 writeIdx wraps), zero-in/zero-out, mono path. Same conventions as `ring_buffer_check`. Now exercises the SIMD `process()` kernel against the analytic oracles.
- `dilog_check` — `dilogNeg`/`dilogSeries` correctness: `dilogNeg(0)==0`, `dilogNeg(1)==-π²/12` (1e-15), the Landen seam across `t=½` (direct series vs Landen partner, both computed explicitly plus the dispatch, 1e-15), `Li₂(-½)`/`Li₂(-0.1)` known values (1e-14), an independent Simpson-quadrature oracle of `-∫₀ᵗ ln(1+u)/u du` over `(0,1]` (substitutes for the inversion FE `Li₂(-t)+Li₂(-1/t)=-π²/6-½ln²t`, which is out of domain for the test points used here since none of {0.2,0.5,0.9} has both `-t` and `-1/t` in `[0,1]`; `long double` is 64-bit on arm64 so a higher-precision series would not help), and strict monotonicity on `(0,1]` (1e5 pts). Same conventions as `ring_buffer_check` (no forced `-O2`, `assert` preconditions armed in Debug). Note: the value `Li₂(-0.1)=-0.09760605976896` is a transcription typo (off by 8.2e-7 — that value is `Li₂(-0.10000086)`); the correct `-0.0976052352293216` is used and is cross-confirmed by the Simpson oracle, so the known-values check is not self-referential.

- `alias_check` — the aliasing measurement, and the harness Commit 11 reads. Feeds a sine, saturates, and reports **inharmonic energy only**: Goertzel at every legitimate harmonic bin `k·f0 < Nyquist` gives the harmonic energy `H`, Parseval gives the total `T`, and the alias energy is `A = T − H`, in dBc against the fundamental. No FFT. Masking the harmonics is essential rather than cosmetic: ADAA's Nyquist droop (2/π per order) attenuates legitimate harmonics too, so a plain THD+N would credit ADAA2 for cleanliness it did not earn; because `H` is *measured* per configuration, the droop cancels out of `A` exactly. **Validity rests on coherent sampling with an ODD bin index**: a nonlinearity driven by a signal that is exactly periodic in the window emits ALL of its energy — aliased or not — on multiples of `f0`, so aliases are separable only by harmonic *index*, and the measurement is sound only if no alias folds onto a masked bin. With `N` a power of two and `k0` odd, `k0` is invertible mod `N`, so harmonics collide only when `k = k'` or `k + k' = N` — i.e. never, below `N/2`. Matrix: `f0 ∈ {55,110,220,440,1k,2k,5k,10k}` Hz × drive `∈ {0,6,12,24,40}` dB × four configurations (the 2× path uses a 513-tap Kaiser β=14 windowed-sinc resampler and is a *measurement* path, not a plugin path). An identity-nonlinearity calibration pass establishes the measurement's own floor (−134 dBc measured, −130 declared; cells at or below it print `< -130` and are clamped in arithmetic so a difference against an immeasurable value cannot manufacture a large apparent gain). Runs in ~2 s.
  **Gate deviates from the spec, deliberately.** The spec nominated 110 Hz / 24 dB for a ≥ 20 dB gate, but that cell cannot carry one: tanh is analytic, so its harmonics decay *exponentially* with drive rather than as `1/k` like a clipper's, and at 110 Hz (221 harmonic slots below Nyquist) the series dies long before the fold point — no-ADAA already measures −121.6 dBc there, essentially at the floor, so there is no aliasing for ADAA2 to remove. That cell is still printed and sanity-checked (ADAA2 must not be worse); the ≥ 20 dB gate moved to **10 kHz / 24 dB** (measured 26.5 dB), where folding actually dominates.
  **Measured conclusions** (relevant to Commit 11): ADAA2 at 1× buys only ~9–15 dB over no-ADAA across most of the band, rising to ~26–31 dB at 10 kHz. ADAA1 at 2× beats ADAA2 at 1× decisively wherever aliasing is measurable — e.g. 24 dB drive at 1 kHz: no-ADAA −30.7, ADAA2 −41.7, ADAA1@2× −84.4 dBc, a 42 dB margin for the oversampled path.
