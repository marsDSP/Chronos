## Project overview

Chronos is a **Nonlinear Delay Engine** JUCE audio plugin (see `README.md`). It is still early, but no longer a bare template: `ChronosProcessor::processBlock` runs a per-sample signal chain of **delay → tanh saturation (ADAA1 or ADAA2 per `adaaOrder`, driven by `drive`) → wet HPF/LPF shaping → equal-power dry/wet mix → output gain → TPDF dither → quantization** to a target bit depth, driven by parameters owned by `ChronosParameters` over an `AudioProcessorValueTreeState`, and `createEditor()` returns a `GenericAudioProcessorEditor`. It targets **Standalone**, **VST3**, and (on macOS) **AU** formats. The header-only DSP lives under `source/dsp/` (the delay line is now `MarsDSP::Delays::SimdDelayLine`, no longer JUCE's `dsp::DelayLine`). C++23.

Identity (set in `CMakeLists.txt`): company `MarsDSP`, BUNDLE_ID `com.marsdsp.Chronos`, manufacturer code `MDSP`, plugin code `CHRO`, version `0.1.0`. Remote: `https://github.com/marsDSP/Chronos.git`, branch `main`.

## Project structure

- `source/` — plugin sources, globbed into the `Chronos` target via `file(GLOB_RECURSE ...)` for `*.{cpp,h,hpp}`.
  - `ChronosProcessor.{h,cpp}` — JUCE `AudioProcessor`. Stereo in/out via `BusesProperties`, mono/stereo layouts supported (the DSP loops over `totalNumInputChannels`, so mono works), no MIDI in/out, not a synth. `getTailLengthSeconds()` returns the current delay time plus a 32768-sample margin for the wet-path SVF ring-down plus `kBudget` samples for the saturator-stage latency-alignment budget (no feedback path, so the tail is the delay time + HPF/LPF ring-down + `kBudget` — the no-feedback branch of the deprecated `DelayEngine::ringoutSamples()`; the `kBudget` term is negligible against the 32768-sample margin but kept separate rather than folded into the constant). `processBlock` early-returns on bypass (the in-place buffer already holds the dry input). The delay is now **block-rate**: once per block `delayLine.setInterpolation(...)` then `delayLine.process(inL, inR, wetL, wetR, n, delay, delay)` runs the whole block through `MarsDSP::Delays::SimdDelayLine` (write-before-read into two `Pow2RingBuffer`s, dual-read sub-block crossfade, internal 20 ms one-pole delay-position smoother) into `wetBufL_`/`wetBufR_`; the delay line owns the position smoothing, so the parameter is handed in raw (block-rate `msToSamples`, no per-sample smoother). The per-sample loop then reads dry from the channel pointers and wet from the wet buffers, applies `drive` (per-sample smoothed linear gain) then tanh saturation (ADAA1 or ADAA2 per `adaaOrder`, two scalar `double` instances per channel; `adaaOrder` is read once before the loop since switching order mid-block would tear the ADAA state), and runs the rest of the chain: shape the saturated wet taps through a stereo-pair SIMD HPF→LPF SVF (Butterworth Q ≈ 0.7071; dry passes unfiltered) → blend dry and wet via an equal-power crossfade (computed with the project's minimax `mmCos`/`mmSin`, not libm) (`dry*cos θ + wet*sin θ`, θ = mix·π/2) → output gain (dB → linear via `Decibels::decibelsToGain`) → per-sample TPDF dither + quantization to the target bit depth, using two independent xorshift32 streams (one per channel, seeded from `std::random_device`). The wet SVF's stereo-pair packing is the only applicable per-sample vectorization (the SVF is a stateful IIR, sequential per channel); the remaining per-sample tail (output gain, TPDF dither, quantization) is scalar by necessity — the xorshift32 streams are sequential per channel (no cross-time SIMD), and `mix`/`gain` are single global values shared by both channels (no cross-channel SIMD gain). The crossfade is comb-filter-free at its extremes (0% = dry only, 100% = wet only); the `mix` parameter defaults to 100% wet so the default path adds no dry and thus introduces no comb filtering. Dry and wet are aligned to a constant latency budget `kBudget = kHalfSampleTaps/2` (8 samples) via `MarsDSP::Align::SaturatorAlign` (`alignL_`/`alignR_`, one per channel): the dry path is delayed by `kBudget` (integer, so `mix = 0%` is bit-transparent apart from the latency — invariant I1), and the wet path is padded to `kBudget` per mode by the aligner placed directly after the saturator (saturator → alignment → SVF): Off pads the wet with an integer `kBudget` delay, ADAA2 with `kBudget − 1` (the ADAA2 triangle kernel supplies 1), and ADAA1 with the `HalfSampleFir` (the box kernel supplies 0.5, the FIR supplies `kBudget − 0.5`). All three wet totals equal `kBudget`, so reported latency is constant across `adaaOrder` (invariant I2, `setLatencySamples(kBudget)` called once in `prepareToPlay`); ADAA1 is now exactly aligned (the 0.5-sample residual the former 1-sample `dryZ1`/`wetZ1` mechanism left is gone — the FIR supplies the missing half sample). `adaaOrder` is read once before the loop and `alignL_`/`alignR_` are `setMode`-ed there (switching mid-block would tear the ADAA state and discontinuously change the alignment configuration); in the mono path `alignR_` is `reset()`/`setMode()`-ed but never called, so it is never fed stale data. `prepareToPlay` calls `delayLine.prepare(sampleRate, samplesPerBlock, ChronosParameters::maxDelayTime)` (5000 ms), resizes the wet buffers to `samplesPerBlock`, resets all four ADAA saturator instances (`adaa1L_`/`adaa1R_`/`adaa2L_`/`adaa2R_`) alongside the SVFs, resets the two `SaturatorAlign` instances (`alignL_`/`alignR_`), and calls `setLatencySamples(MarsDSP::Align::SaturatorAlign::kBudget)`. `getBypassParameter()` is overridden to return the bypass param so hosts wire it natively. Parameters live in an `AudioProcessorValueTreeState` whose layout is built by `ChronosParameters::createParameterLayout()` and accessed via a `ChronosParameters` member: `gain` (float, −12…+12 dB), `bits` (int, 1…32), `delayTime` (float, 5…5000 ms), `hpfFreq` (float, 20…2000 Hz), `lpfFreq` (float, 200…20000 Hz), `mix` (float, 0…100%, default 100% wet), `interpolation` (choice: Linear / Lagrange 3rd / Lagrange 5th, default Lagrange 5th), `drive` (float, 0…40 dB, default 0; smoothed as linear gain via `Decibels::decibelsToGain`, matching `gain`), `adaaOrder` (choice: Off / 1st / 2nd, default 2nd), and `bypass` (bool); the `GenericAudioProcessorEditor` renders the choice as a combobox. `isBusesLayoutSupported` is `protected`, matching the base class. `getStateInformation`/`setStateInformation` are still stubs; programs are the single default program.
  - `ChronosParameters.h` — owns the APVTS parameter IDs and `createParameterLayout()`, casts the `AudioParameterFloat`/`Int`/`Bool`/`Choice` pointers in its constructor (via a `castParameter` helper, `jassert`-checked), and exposes smoothed, audio-thread-safe accessors. `prepare(sr)` stores the sample rate and sets a ~20 ms ramp on the gain/bits/hpf/lpf/mix/drive smoothers (delay is no longer smoothed here — the `SimdDelayLine` owns its 20 ms one-pole position ramp); `reset()` snaps them to the current stored values and sets the raw block-rate `delaySamples` from `msToSamples(delayParam->get())`; `update()` aims them at the current knob positions (once per block) and refreshes `delaySamples`; `smoothen()` advances the six per-sample smoothers. Delay time is read in samples via `msToSamples` (block-rate, unsmoothed); `mix` is smoothed as a raw 0–100 value and converted to an equal-power angle in the processor. `getInterpolation()` maps the choice index to `MarsDSP::Delays::Interpolation` (null-guarded, defaults to Lagrange5th). `getADAAOrder()` returns the choice index 0/1/2 (null-guarded, defaults to 2). `getDrive()` returns the smoothed linear gain. All raw-parameter reads are null-guarded. Exposes `getBypassParameter()` for the processor's override.
  - `ChronosEditor.{h,cpp}` — JUCE `AudioProcessorEditor` from the template. Note the processor does not instantiate it; `createEditor()` returns a `GenericAudioProcessorEditor` instead.
  - `math/Trigonometry.h` — `mmSin`, `mmCos`, `mmTan`: rational minimax approximations, each with a `float` and an `M128` overload, all evaluated as a Horner series in x² and sharing the FMA helper `mulAdd` (which calls the `FMADD` macro). `mmSin` is [7/6] odd on [−π, π] (float32 max abs err 3.2e-07); `mmCos` is [6/6] even on [−π, π] (3.5e-07); `mmTan` is [7/6] odd on [−1.55, 1.55], fitted for **relative** error because tan diverges at ±π/2 — its `Q(x²)` carries a root at ±π/2 to reproduce the pole, so callers must range-reduce and never pass |x| ≥ π/2. Coefficient namespaces are `Minimax{Sin,Cos,Tan}Coeffs`, with `minimax{Sin,Cos,Tan}Approx` as the scalar kernels. Caveat: `mmTan` is rounding-limited rather than coefficient-limited near the pole — `Q` falls to 0.023 at x = 1.55, so float32 cancellation caps relative error at ~3.9e-06 there (~1.9e-07 for |x| ≤ 1.0) no matter how good the coefficients are. `simd/Config.h` — the SIMD abstraction layer, providing the `MM()` / `M128` macros over native SSE or SIMDe, plus the `FMADD` fused multiply-add alias (`simde_mm_fmadd_ps`); it is the single place that pulls in `<simde/x86/fma.h>`, so call sites use `FMADD(a,b,c)` rather than naming `simde_mm_fmadd_ps` directly. Both `math/Trigonometry.h` (via `SVF.h`'s `mmTanScalar`) and `simd/Config.h` (via `SimdDelayLine.h` and `SVF.h`) are now `#include`d by the plugin.
  - `math/Dilogarithm.h` — `MarsDSP::Math::dilogSeries`/`dilogNeg`, Landen-folded `Li₂(-t)` for `t∈[0,1]` (needed by `TanhNL::F2`, since the second antiderivative of tanh has no elementary form); `dilogSeries` is a fixed 50-term reverse-Horner `Σ v^k/k²` (`|v|≤0.5`, data-independent loop count so a future hot path is latency-bounded), and `dilogNeg` uses the direct series for `t≤½` and the Landen partner `-½·ln²(1+t) - series(t/(1+t))` for `t>½`, agreeing to ~1e-16 across the `t=½` seam. JUCE-free.
  - `dsp/` — header-only DSP, now wired into the plugin: `DelayInterpolator.h` (6-tap Lagrange/Linear coefficient generator, centred evaluation point `e = 3 - f`), `OnePoleSmoother.h` (exponential one-pole with `processN`/sub-block cache), `Pow2RingBuffer.h` (single-channel pow2 ring with conditional mirror refresh + two-memcpy window reads), `SimdDelayLine.h` (scalar block delay line over two `Pow2RingBuffer`s, dual-read sub-block crossfade, internal 20 ms one-pole position smoother, used by `ChronosProcessor`), and `SVF.h` (`OnePoleTPT`, `SimdSVF` — the latter used by `ChronosProcessor` for the wet HPF/LPF). `SimdDelayLine` has two evaluation kernels compiled in: the production `process()` runs a 4-wide SIMD inner loop (one aligned `load_ps` + five `loadu_ps` per tap window, broadcast coefficients, FMA accumulate, lipol-style `out = vOld + alpha*(vNew-vOld)` fade, precomputed per-lane alpha ramp, scalar tail for `subN % 4`), and `processScalar()` keeps the scalar `dot6` path for A/B; a `static constexpr bool kUseSimd = true` flag (flip + recompile) selects the production path. Parity is to a tolerance, not bit-exact, because the MAC tree reassociates.
  - `dsp/align/` — header-only latency-alignment DSP for the saturator stage (not yet wired into the plugin). `HalfSampleFir.h` (`MarsDSP::Align`): symmetric half-sample-delay FIR that will compensate ADAA1's 0.5-sample box-kernel wet-path latency. Coefficients are a 16-tap Kaiser-windowed sinc at offset `D = (N−1)/2` (β ≈ 3.6, chosen by `scripts/python/halfsample_fir.py` to minimise max passband deviation over `[0, 0.42·fs]`; +0.046 dB at 15 kHz, structural Nyquist null at π), re-derived and regression-checked by that script. Symmetric by construction (`N` even ⇒ `D` half-integer ⇒ `sinc(m−D)` never hits the `sinc(0)` degenerate case, and the Kaiser window is symmetric), so the FIR is exact linear phase with group delay `(N−1)/2 = 7.5` samples — a half sample of intended fractional delay plus 7 samples of integer bulk delay. The tap line is a `memmove` shift (newest at index 0) with the coefficient pairs folded (`h[j]·(z[j] + z[N−1−j])`) so the multiply count halves and the accumulation is structurally symmetric and cannot drift from linear phase through FMA reassociation. `kHalfSampleTaps` (even, `static_assert` ≥ 4) and `kHalfSampleCoeffs` are `inline constexpr`; `kBulkDelay = kTaps/2 − 0.5` is the FIR's own group delay. Only ADAA1 will run the FIR; Off and ADAA2 modes use integer delays (exact). `ShortDelay.h` (`MarsDSP::Align`): a fixed-capacity integer delay template `ShortDelay<MaxDelay>` for the 0…`MaxDelay` sample range — deliberately not `SimdDelayLine` (block-rate, one-pole smoother, 6-tap interpolator, dual-read crossfade — none apply to a fixed integer delay, and coupling the alignment layer to the main delay engine is unwanted). `setDelay(0)` is a bit-exact passthrough (returns `x` directly, no ring round-trip — the off-by-one the spec flags as the most likely bug in the whole layer; a read-then-write ring with `d == 0` would silently hand back a full-ring delay instead of zero); `d ≥ 1` is read-then-write into a `MaxDelay+1` ring, tap at `(w − d + cap) % cap`. Used by `SaturatorAlign` for the wet-path integer padding in Off and ADAA2 modes (and to leave ADAA1's wet at 0 integer delay so the FIR supplies the rest). `SaturatorAlign.h` (`MarsDSP::Align`): one instance per channel (matching the ADAA classes), tying the dry/wet latency alignment together. `kBudget = kHalfSampleTaps/2` (the constant reported latency; `static_assert kBudget >= 2` so ADAA2's `kBudget−1` integer delay stays ≥ 1). `processDry` always applies the integer delay `kBudget`; `processWet` is mode-dependent — `setMode(0)` (Off) → `wetInt_` at `kBudget` (FIR unused), `setMode(1)` (ADAA1) → `wetInt_` at 0 + the `HalfSampleFir` (the only mode that runs the filter), `setMode(2)` (ADAA2) → `wetInt_` at `kBudget−1` (FIR unused). Wet totals: Off `kBudget`, ADAA1 `0.5 + (kBudget−0.5) = kBudget`, ADAA2 `1 + (kBudget−1) = kBudget` — all equal `kBudget` and to dry, so reported latency is constant (I2) and dry/wet are aligned (I1). The FIR runs in mode 1 only, not in all modes, so its HF droop is not imposed on the two exact integer modes. Wet-chain order for the plugin: saturator → alignment → SVF (the layer is LTI so its position relative to the SVF is acoustically irrelevant, but directly after the saturator gives the "saturator stage" one well-defined total latency). Switching `adaaOrder` mid-stream discontinuously changes both the alignment configuration and the saturator kernel, so a small click is expected; a dual-chain crossfade to smooth it is a separate feature (documented in the header, out of scope here). Verified by `align_check` (Commit 4); wired into `ChronosProcessor` in Commit 5 (replacing the former 1-sample `dryZ1`/`wetZ1` mechanism). JUCE-free; links against `SharedCode`. NaN/inf hygiene: `SaturatorAlign::process{Dry,Wet}` scrub non-finite inputs to +0.0f, and `SimdSVF::processBlockStep` clears non-finite input lanes and resets latched non-finite state (never taken for finite signals — bit-exact), so a bad host sample can no longer latch the chain's IIR state.
  - `dsp/nonlinear/` — header-only nonlinear / antiderivative-antialiasing (ADAA) DSP. `Nonlinearities.h` (`MarsDSP::Nonlinear`): ADAA nonlinearity policies supplying `f`/`F1`/`F2` (all `double`) — `TanhNL` (`f = tanh`, `F1 = |x| - ln2 + log1p(exp(-2|x|))` overflow-safe, `F2 = sign(x)·[x²/2 - |x|·ln2 + G(|x|)]` with `G(a) = ½·Li₂(-e⁻²ᵃ) + π²/24` via `math/Dilogarithm.h`; `G` bounded by 0.412 for all `x`) and `AlgebraicNL` (`f = x/√(1+x²)`, all-elementary `F1 = √(1+x²)`, `F2 = ½(x√(1+x²) + asinh x)` — the `Li₂` escape hatch and a second curve for the alias harness). `F1′ = f`, `F2′ = F1`; `F1` even, `F2` odd; `signx(0)=0` makes `F2(0)=0` exact. `ADAA1.h` (`MarsDSP::Nonlinear::ADAA1<NL>`): first-order ADAA baseline — divided difference of `F1` over the last two samples, midpoint `f(0.5·(x0+x1))` fallback when `|x0-x1| < 1e-4`, evaluates `F1(x0)` **unconditionally** (one `F1` eval per sample) and caches it on every path — skipping the eval on the fallback path would leave `F1x1_` holding `F1` of an older input than `x1_`, and a signal whose per-sample steps stay under the epsilon lets `x1_` drift arbitrarily far from the cached value; `alias_check` measured the resulting broadband error at −34 dBc on a 55 Hz sine (−121.8 dBc after the fix); half-sample (fractional) latency, so it is the `alias_check` A/B comparison path, not a release-quality one (the 0.5-sample residual against a 1-sample dry delay cannot be made integer). `ADAA2.h` (`MarsDSP::Nonlinear::ADAA2<NL>`): second-order ADAA — twice the second divided difference of `F2` over the last three samples `x0,x1,x2`, output aligned to `x1` for exactly 1 sample of **integer** latency (`kLatencySamples = 1.0`). Four branches in load-bearing order (`A=|x0-x1|`, `B=|x1-x2|`, `C=|x0-x2|`): (a) all three nodes coincident (`A<εᵢ` and `B<εᵢ`) → centroid `f((x0+x1+x2)/3)` (`O(Δ²)` residual vs a midpoint's `O(Δ)`; must precede (b), since small `A`,`B` imply small `C`); (b) confluent outer nodes (`C<ε₀`, the Nyquist-rate `…a,b,a,b…` alternation heavy saturation produces) → Hermite form `2·(F1(m02) - d1)/(m02 - x1)` with `m02 = ½(x0+x2)`; (c) inner quotient degenerate (`A<εᵢ` only) → `d1 = F1(½(x0+x1))`, folded into the `d1` assignment so it needs no separate arm; (d) generic formula. Caching identity: this sample's `d2` is last sample's `d1` (both `F2[x1,x2]`), cached after its own fallback, so one `F2` eval + one inner + one outer quotient run per sample and the symmetric `B<εᵢ` case is free. `εᵢ = 1e-4`, `ε₀ = 1e-6` (`kEpsInner`/`kEpsOuter`), both tuned in `adaa2_check` and justified in the header comment: each epsilon sits where its fallback's truncation balances the cancellation of the exact formula it replaces. `ε₀` is **not** the spec's initial `1e-4` — branch (b) evaluates `F1` at `m02` but reuses `d1 = F2[x0,x1]`, which is first-order inconsistent once `x0 ≠ x2`, so it truncates at `O(C)` (`|y|·C/(2|m02-x1|)`), not `O(C²)`; at `1e-4` that measured 8.4e-6 (~−101 dB) where the generic formula would have given ~1e-7. Making the branch consistent (recomputing `d1` as `F2[m02,x1]`, one extra `F2` eval on that path only) would restore `O(C²)` and allow a larger `ε₀`. `double` internally — the nested divisions carry a `1/Δ²` cancellation term, so float32 would fire the coincident-node fallback for most samples at ordinary drive. `reset()` zeros all four state members (`x1_`,`x2_`,`F2x1_`,`d2_`). Verified by `adaa2_check`; no plugin wiring yet — a header the plugin does not include. JUCE-free; links against `SharedCode` like the rest of `source/dsp/`.

Python 3 is required (`find_package(Python3 COMPONENTS Interpreter REQUIRED)`); Boost and Doxygen are NOT required.

## Build

Chronos builds with CMake + JUCE. C++23, CMake ≥ 3.23.1. The primary workflow is CLion (`cmake-build-debug/`); standard CMake also works.

### Prerequisites

- A C++23 toolchain (Xcode Command Line Tools on macOS).
- CMake ≥ 3.23.1 (Ninja optional; CLion ships its own generator).
- Python 3 (required by `CMakeLists.txt`).

### Targets

- `Chronos_Standalone`, `Chronos_VST3`, `Chronos_AU` (macOS only), `Chronos_All` — the plugin formats.
- `AudioPluginHost` — built from `libs/JUCE/extras/AudioPluginHost` (opt-in via `-DBUILD_AUDIO_PLUGIN_HOST=ON`; OFF is the default).
- `Run_AudioPluginHost_VST3` / `Run_AudioPluginHost_AU` (macOS) — build the plugin + host, then open `Audio Plugin Host.app` for scanning.
- `Print_Plugin_Paths` — prints the VST3/AU artifact locations.

Built plugins are written to `<build>/Chronos_artefacts/<Config>/` as **Standalone**, **VST3**, and (on macOS) **AU** (e.g. `cmake-build-debug/Chronos_artefacts/Debug/VST3/Chronos.vst3`).

### macOS / build gotchas (read before touching CMake)

- **Universal binary**: `CMAKE_OSX_ARCHITECTURES` is forced to `x86_64;arm64`; deployment target `11.0` (including the arm64 slice).
- **x86_64 FMA**: the plugin and harness targets compile with FMA enabled on all platforms so `simde_mm_fmadd_ps` lowers to `vfmadd*ps` on x86_64 (arm64 has FMA unconditionally and needs no flag). Apple uses `-Xarch_x86_64 -mfma` (the `-Xarch_` prefix scopes the flag to the x86_64 slice of the universal build; a bare `-mfma` would also reach the arm64 pass); Linux x86_64 uses bare `-mfma`; MSVC x64 uses `/arch:AVX2`. This raises the x86_64 baseline to Haswell/FMA3 (AVX2 on MSVC) — pre-Haswell CPUs (e.g. the 2013 Mac Pro, Ivy Bridge-EP, which has AVX but no FMA3) would take a SIGILL, so drop the flag if such hardware must keep working. Without it the code still builds — SIMDe falls back to a mul+add pair.
- **Warnings**: `-w` disables all warnings on non-MSVC compilers; JUCE recommended warning/LTO flags are still applied to the plugin target.
- **Debug symbols**: `-gdwarf-4` is added in `Debug`.
- **ObjC ARC**: on Apple, JUCE `.mm` sources and the plugin target are compiled with `-fno-objc-arc`.
- **Policy overrides**: `CMP0177` (install `DESTINATION` normalization) and `CMP0167` (Boost) are set to `NEW`. `CMAKE_POLICY_VERSION_MINIMUM` is not set, since no vendored lib currently needs it.
- **Submodule ordering**: `add_subdirectory(libs/JUCE)` runs at the top of `CMakeLists.txt`, before the macOS arch/deployment-target cache variables are set. This configures fine today, but if you add a vendored lib that reads `CMAKE_OSX_ARCHITECTURES` / `CMAKE_OSX_DEPLOYMENT_TARGET` at configure time, move those cache variables above its `add_subdirectory()`.
- **Post-build copy**: a `POST_BUILD` command on `Chronos_VST3` runs `scripts/bash/copy_vst3.sh`, gated by `-DCOPY_VST3_AFTER_BUILD=ON` (default OFF). The script takes the VST3 bundle path (`$1`, from CMake's `$<TARGET_BUNDLE_DIR:...>`) and the destination (`$2`, from the `VST3_COPY_DEST` cache variable, default `~/Desktop/vst test`).
- **JUCE submodule**: `libs/JUCE` is a marsDSP fork. If it is empty after clone, run `git submodule update --init --recursive`.

## Testing

Opt-in harnesses, gated by `-DBUILD_TEST_HARNESSES=ON` (OFF by default, so the default build is unchanged). `tests/CMakeLists.txt` defines sixteen executables. Fifteen link only the `SharedCode` INTERFACE target (no JUCE), so they pull in the `source/` + `libs/simde` include paths and `cxx_std_23` without the plugin modules; `delay_line_bench` additionally links `juce::juce_dsp` to get `juce::dsp::DelayLine` for the old-baseline comparison:

- `tan_bench` — `mmTan` (FMA `M128`) accuracy regression + throughput vs `std::tan`; forced `-O2` and `-Xarch_x86_64 -mfma` so the kernel inlines and `simde_mm_fmadd_ps` lowers to a fused multiply-add.
- `ring_buffer_check` — `Pow2RingBuffer` correctness vs a naive modulo oracle (zero state, block write + mirror invariant, exhaustive window read, interleaved sequence, large capacity). No forced `-O2` so the header's `assert` preconditions stay armed in a Debug configure.
- `halfsample_fir_check` — `HalfSampleFir` correctness: coefficient symmetry (bit-exact), DC gain, impulse-response centroid (`(N−1)/2`), flat group delay (< 1e-9 ripple over `[0, 0.9π]`), passband magnitude (gate > −0.1 dB at 15 kHz), Nyquist null, a dormant Lagrange cross-check at `kHalfSampleTaps == 6`, and reset reproducibility. Same conventions as `ring_buffer_check` (no forced `-O2`, `assert`/`static_assert` preconditions armed in Debug).
- `short_delay_check` — `ShortDelay<MaxDelay>` correctness: for every `d` in `[0, MaxDelay]`, impulse (exactly `1.0f` at sample `d`, `0.0f` elsewhere in `[0, 4·MaxDelay]`), ramp (`y[n] == x[n−d]` bit-exact over 1000 samples, many ring wraps), and reset reproducibility. Tested at `MaxDelay = 8` (the real `kBudget`) and `MaxDelay = 1` (the `d ∈ {0,1}` edge). Same conventions as `ring_buffer_check` (no forced `-O2`, `assert` preconditions armed in Debug).
- `align_check` — `SaturatorAlign` correctness: the property the whole layer exists for. (1) dry is an exact integer delay (impulse → `1.0f` at `kBudget`, zeros elsewhere, all three modes, bit-exact — I1); (2) wet total group delay equals `kBudget` in every mode (the ADAA stage kernel is prepended analytically — box `[0.5,0.5]` for ADAA1, triangle `[0.25,0.5,0.25]` for ADAA2 — before the alignment wet impulse response; centroid `== kBudget` to 1e-6, the headline test); (3) modes 0/2 are bit-exact pure delays (impulse → single `1.0f` at `kBudget`/`kBudget−1`); (4) mode 1 is linear phase (group-delay ripple < 1e-6 over `[0, 0.45·fs]` — I3); (5) dry/wet null (mode 0, same white-noise to both paths, bit-identical); (6) cross-mode phase coherence at 1/5/10/15 kHz (50/50 sum within 0.5% of the in-phase prediction — the test that would have caught a first-order-allpass design); (7) reset across all modes; (8) mode switching mid-stream (no NaN, bounded). Same conventions as `ring_buffer_check` (no forced `-O2`, `assert` preconditions armed in Debug).
- `latency_null_check` — end-to-end latency/alignment harness (`harnesses/dsp/latency_null_check.cpp`). Links `SharedCode` only and hand-assembles the DSP headers into the same chain order as `processBlock` (delay → saturator → alignment → [SVF] → equal-power crossfade), NOT the JUCE `AudioProcessor`. (1) full-dry null (`mix = 0%`: output == input delayed by `kBudget`, bit-exact, all three modes identical = I2); (2) full-wet Off saturator-bypassed (output == input delayed by `delaySamples + kBudget`, to 1e-5); (3) 50% mix Off sine sweep 20 Hz–20 kHz, gate ±0.05 dB (the acceptance test — any residual misalignment appears as a comb); (4) 50% mix ADAA1/ADAA2 small-signal sweep to 15 kHz, gate ±0.2/±0.1 dB. Tests 3–4 compare the 50% sum against the predicted in-phase sum of dry-only and wet-only (measured separately), which cancels the ADAA kernel's own low-pass droop (box `|cos(πf/fs)|` for ADAA1, triangle `cos²(πf/fs)` for ADAA2 — −2.2/−3.7 dB at 15 kHz in the raw 50/50 sum) and isolates alignment, which is the spec's intent ("a failure here that passes test 3 means the mode-dependent branch in `setMode` is wrong"); the spec's literal "near-flat" wording is unachievable for ADAA1/ADAA2 because the kernels droop. The wet SVF and dither/quant tail are wired into the chain but gated off (LTI / signal-orthogonal, sit after the aligner on the wet path only, cannot affect alignment; enabling them would confound the tolerances). Same conventions as `ring_buffer_check` (no forced `-O2`).
- `simd_delay_check` — `SimdDelayLine` correctness: integer impulse (3 modes), polynomial reproduction / centroid (3 modes, the flaw-B sign-error guard), stereo independence, multi-block delay, delay-move settling (20 ms one-pole convergence), ring-wrap endurance (~250 writeIdx wraps), zero-in/zero-out, mono path. Same conventions as `ring_buffer_check`. Now exercises the SIMD `process()` kernel against the analytic oracles.
- `dilog_check` — `dilogNeg`/`dilogSeries` correctness: `dilogNeg(0)==0`, `dilogNeg(1)==-π²/12` (1e-15), the Landen seam across `t=½` (direct series vs Landen partner, both computed explicitly plus the dispatch, 1e-15), `Li₂(-½)`/`Li₂(-0.1)` known values (1e-14), an independent Simpson-quadrature oracle of `-∫₀ᵗ ln(1+u)/u du` over `(0,1]` (substitutes for the inversion FE `Li₂(-t)+Li₂(-1/t)=-π²/6-½ln²t`, which is out of domain for the test points used here since none of {0.2,0.5,0.9} has both `-t` and `-1/t` in `[0,1]`; `long double` is 64-bit on arm64 so a higher-precision series would not help), and strict monotonicity on `(0,1]` (1e5 pts). Same conventions as `ring_buffer_check` (no forced `-O2`, `assert` preconditions armed in Debug). Note: the value `Li₂(-0.1)=-0.09760605976896` is a transcription typo (off by 8.2e-7 — that value is `Li₂(-0.10000086)`); the correct `-0.0976052352293216` is used and is cross-confirmed by the Simpson oracle, so the known-values check is not self-referential.
- `nonlinearity_check` — ADAA policy (`TanhNL`/`AlgebraicNL`) `f`/`F1`/`F2` correctness: `F1′=f` and `F2′=F1` by central difference (h=1e-5) over `[-20,20]` (combined abs/rel tol 1e-6); parity `F1(-x)==F1(x)` and `F2(-x)==-F2(x)` bit-exact over 1e5 pts; `F2(0)==0` exactly and `F1(0)` equals the policy's defining value (0 for `TanhNL`, 1 for `AlgebraicNL` — `F1(0)==0 for each policy` would be inconsistent with `AlgebraicNL`'s `F1=√(1+x²)` which gives `F1(0)=1`, so the per-policy value is used); `F1`/`F2` finite at ±700/±1000 (catches a naive `log(cosh)`); and the `TanhNL` tail at `|x|=8` (`|F1(8)-(8-ln2)| = log1p(e⁻¹⁶) ≈ 1.13e-7 < 2e-7`, plus the `G`-tail bound `|G(8)-π²/24| < 6e-8` — 6e-8 is the `G`-tail bound, not the `F1`-tail bound). Same conventions as `ring_buffer_check`/`dilog_check` (no forced `-O2`, `assert` preconditions armed in Debug).
- `adaa2_check` — `ADAA2` (and, for the static curve, `ADAA1`) correctness over `TanhNL` and `AlgebraicNL`. **Oracle**: Hermite–Genocchi, `y = 2·F2[x0,x1,x2] = 2∫_simplex f`, i.e. the mean of `f` over the triangle the three nodes span — cancellation-free by construction, unlike the `long double` replay the spec suggested (`long double` is 64-bit on arm64, so that would be bit-identical to the code under test). Two evaluated forms, each verified against `f(x)=x` where `y` must equal the node centroid: for span ≥ 0.5 the inner direction is integrated analytically via `F1`, leaving `y = 2/(x2-x1)·∫₀¹[F1(x0+(x2-x0)t) - F1(x0+(x1-x0)t)]dt` with the node list permuted (the divided difference is symmetric) so the widest-separated pair lands in the denominator; for span < 0.5 the 2-D tensor form in `f` directly. Both use composite Gauss–Legendre-16 with panels sized to ≤ 1.0 in `x`, nodes from a Newton solve on the Legendre recurrence (no transcribed tables). Sections: (1) static curve settles to `f(x)` within 1e-13 over `[-40,40]`; (2) branch (b), the confluent `x0=x2=a, x1=b` Nyquist pattern, on a log grid `|a-b| ∈ [1e-6,20] × a ∈ [-20,20]`; (3) seam continuity, 1000 steps across each epsilon, gating both the error and the *output step* against the oracle's own step; (4) an error surface over `x_k = A sin(ω(n-k))`, `A ∈ [0.1,40] × ω ∈ [1e-4,π]`; (5) 10648 degenerate coincidence patterns incl. ±700; (6) `reset()` bit-exactness; (7) odd symmetry bit-exact. **Tolerances are a per-point error model**, not a constant — achievable accuracy swings ten orders of magnitude with node spacing — and the gate is on `err/bound` (slack 40×) plus an absolute surface gate of 1e-3. Measured: max `err/bound` 1.00; surface max |err| **3.095e-4, identical for both policies** (so it is a property of the branch structure, not the curve), at `A ≈ 1.4` near-Nyquist, where the inner gaps straddle `εᵢ` while `C` is ~60× smaller, so branch (c)'s `A²/24` truncation enters one inner quotient and is then amplified by the outer `2/C` (symmetric truncation would cancel — it is the asymmetry across the seam that costs); ~2e-5 at `|x| ≈ 40`. The error model also has to account for `TanhNL::F2` being **absolutely** accurate only to ~`u` near `x=0` (three ~0.4-sized terms cancel down to `x³/6`), not to `u·|F2|`. Same conventions as `ring_buffer_check` (no forced `-O2`); runs in ~0.5 s.
- `adaa_bench` — `ADAA1<TanhNL>`, `ADAA2<TanhNL>`, `ADAA2<AlgebraicNL>`, and plain `std::tanh` throughput (ns/sample, min of 5 reps) on a 48 kHz exponential sine sweep, plus the `ADAA2` branch histogram ((a) centroid / (b) confluent / (c) inner-mid / (d) generic) on the same sweep at drives {0, 6, 12, 24, 40} dB. Branch selection depends only on input node spacing, not on the NL policy, so the histogram is reported once. Reuses `tan_bench`'s timing idiom (steady_clock, `doNotOptimize` barrier, min-of-5-reps, sink accumulators); forced `-O2` and `-Xarch_x86_64 -mfma` so the `ADAA2` template and the 50-term dilogarithm series inline. Informational only — no pass/fail gate. On the reference machine: `std::tanh` ~4.4 ns/sample, `ADAA1<TanhNL>` ~9.6 ns, `ADAA2<TanhNL>` ~75 ns (17× tanh; the dilog series is ~87% of the cost — `ADAA2<AlgebraicNL>` at ~10 ns has no dilog), i.e. ~0.7% of a core at 48 kHz stereo. The histogram shows (d) generic dominating (>99.6%) at all drives, (a) dropping from 0.23% at 0 dB to 0% at 40 dB, (b) firing ~0.0001% — rare on a feedforward sine, expected since the Nyquist `...a,b,a,b...` alternation is a saturation artifact, not a sine property.
- `alias_check` — the aliasing measurement, and the harness Commit 11 reads. Feeds a sine, saturates, and reports **inharmonic energy only**: Goertzel at every legitimate harmonic bin `k·f0 < Nyquist` gives the harmonic energy `H`, Parseval gives the total `T`, and the alias energy is `A = T − H`, in dBc against the fundamental. No FFT. Masking the harmonics is essential rather than cosmetic: ADAA's Nyquist droop (2/π per order) attenuates legitimate harmonics too, so a plain THD+N would credit ADAA2 for cleanliness it did not earn; because `H` is *measured* per configuration, the droop cancels out of `A` exactly. **Validity rests on coherent sampling with an ODD bin index**: a nonlinearity driven by a signal that is exactly periodic in the window emits ALL of its energy — aliased or not — on multiples of `f0`, so aliases are separable only by harmonic *index*, and the measurement is sound only if no alias folds onto a masked bin. With `N` a power of two and `k0` odd, `k0` is invertible mod `N`, so harmonics collide only when `k = k'` or `k + k' = N` — i.e. never, below `N/2`. Matrix: `f0 ∈ {55,110,220,440,1k,2k,5k,10k}` Hz × drive `∈ {0,6,12,24,40}` dB × four configurations (the 2× path uses a 513-tap Kaiser β=14 windowed-sinc resampler and is a *measurement* path, not a plugin path). An identity-nonlinearity calibration pass establishes the measurement's own floor (−134 dBc measured, −130 declared; cells at or below it print `< -130` and are clamped in arithmetic so a difference against an immeasurable value cannot manufacture a large apparent gain). Runs in ~2 s.
  **Gate deviates from the spec, deliberately.** The spec nominated 110 Hz / 24 dB for a ≥ 20 dB gate, but that cell cannot carry one: tanh is analytic, so its harmonics decay *exponentially* with drive rather than as `1/k` like a clipper's, and at 110 Hz (221 harmonic slots below Nyquist) the series dies long before the fold point — no-ADAA already measures −121.6 dBc there, essentially at the floor, so there is no aliasing for ADAA2 to remove. That cell is still printed and sanity-checked (ADAA2 must not be worse); the ≥ 20 dB gate moved to **10 kHz / 24 dB** (measured 26.5 dB), where folding actually dominates.
  **Measured conclusions** (relevant to Commit 11): ADAA2 at 1× buys only ~9–15 dB over no-ADAA across most of the band, rising to ~26–31 dB at 10 kHz. ADAA1 at 2× beats ADAA2 at 1× decisively wherever aliasing is measurable — e.g. 24 dB drive at 1 kHz: no-ADAA −30.7, ADAA2 −41.7, ADAA1@2× −84.4 dBc, a 42 dB margin for the oversampled path.
- `simd_delay_parity` — SIMD `process()` vs scalar `processScalar()` parity: two identically-prepared instances run in lockstep across block sizes {1,4,7,12,16,17,23,24,64,100,256}, fractional delays, stereo, mono, ring-wrap (small capacity, 4000 blocks), and the delay-move crossfade region. Compares to a 1e-5 abs tolerance (parity is to a tolerance, not bit-exact, because the MAC tree reassociates). Forced `-O2` and `-Xarch_x86_64 -mfma`, matching `tan_bench`.
- `delay_line_bench` — `SimdDelayLine` throughput vs the old `juce::dsp::DelayLine` per-sample path (the exact pre-port `processBlock` shape: per-sample `setDelay` + `pushSample` + `popSample` × 2 ch, default Linear) plus SIMD-vs-scalar and per-mode (Linear/Lag3/Lag5) SIMD cost. Stereo, 48 kHz, block 256, fractional delay 347.5, min-of-5-reps ns/sample. First harness to link a JUCE module (`juce::juce_dsp`); `SharedCode` propagates the JUCE module config defines via INTERFACE so `<juce_dsp/juce_dsp.h>` includes directly. Forced `-O2` and `-Xarch_x86_64 -mfma`. Gate: SIMD ns/sample ≤ 1.05× scalar (regression check); the juce ratio is informational. On the reference machine the SIMD Lag5 kernel measured ~4.0 ns/sample, scalar ~6.1 ns (SIMD ~1.5× over scalar), and `juce::dsp::DelayLine` ~9.3 ns (SIMD ~2.3× over the old per-sample path); per-mode SIMD cost varied Linear ~2.9 < Lag3 ~2.9 < Lag5 ~4.1 ns (max/min ~1.4×, so Linear's zero-padded 6-MAC path is not a liability).
- `chain_bench` — stage-attributed end-to-end throughput benchmark (`harnesses/perf/chain_bench.cpp`). Hand-assembles the full DSP chain in `processBlock` order (delay → drive-gain → ADAA → align → HPF → LPF → crossfade → gain+dither+quant) with scalar `LinRamp` stand-ins for the JUCE smoothers (flat ramps = settled-smoother steady state, documented in the header), links `SharedCode` only. Reports ns/sample per stage in isolation (streaming recorded real stage inputs) plus the full fused chain, over `adaaOrder` × `mix` × `blockSize` × mono/stereo. Same timing idiom as `tan_bench` (steady_clock, `doNotOptimize`, min-of-5-reps, forced `-O2`/`-mfma`); `--csv <path>` writes a diffable CSV. Informational only — no pass/fail gate (exits non-zero only if the untimed recording pass goes NaN/inf). Registered with CTest under label `bench`.
- `chain_fuzz_check` — adversarial-input safety net (`harnesses/dsp/chain_fuzz_check.cpp`). Feeds the hand-assembled chain (same order as `processBlock`, flat parameters, harness-only dither kill switch) a battery of hostile inputs over `adaaOrder` × drive × mix × delay: all zeros, denormals (`1e-320` — flushes to ±0 in the float buffer — and true float denormal `1e-45`), full-scale ±1.0/±10.0, ±inf/NaN injected at samples 0/1/2/mid-block, DC at every power of two from `2^-30` to `2^0`, Nyquist alternation (fires ADAA2 branch (b); also at block 61 to force the SIMD delay's scalar tail), a `1e6` impulse, block-boundary step discontinuities, and unsmoothed mid-stream parameter steps (delay/drive/mode — harsher than the plugin). Gates: no NaN/inf for any finite input, output within an analytically derived bound (dry is bit-exact; ADAA is a mean of `|tanh| ≤ 1` over the node simplex; 3.0× measured SVF cascade allowance (square waves swing edge-to-edge through the HP band, measured worst 2.44×); +2·lsb dither/round), and zeros-in → `+0.0f`-out bit-exact with dither off (`|out| ≤ lsb` with dither on, by design). NaN/inf robustness is GATED: injected ±inf/NaN must leave every output sample finite and rejoin the zeroed-reference trajectory within `pos + delaySamples + 300` samples (tol 1e-2) — previously one NaN latched the chain forever via the SVF's IIR state; the scrubs noted in the align bullet fixed that. Re-run after every DSP change. Same conventions as `ring_buffer_check` (no forced `-O2`), one deviation: NDEBUG is forced ON for this target (the NaN/inf battery intentionally violates DSP header preconditions; recovery measurement needs IEEE propagation, not an assert abort).

Build & run: `cmake -S . -B build-tests -DBUILD_TEST_HARNESSES=ON && cmake --build build-tests --target tan_bench ring_buffer_check halfsample_fir_check short_delay_check align_check latency_null_check chain_fuzz_check simd_delay_check dilog_check nonlinearity_check adaa2_check adaa_bench alias_check simd_delay_parity delay_line_bench chain_bench` then run each binary; exit 0 = pass. The placeholder subdirectories (`benchmarks/`, `charts/`, `logs/`) remain empty. `Catch2` is vendored under `libs/` for future numeric verification.
